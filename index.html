Mik Mak Muk

A 160 GB bare-metal CachyOS homelab cluster built on three HP Mini PCs. No heavy hypervisors, no cloud lock-in—just Ansible, custom kernel tuning, zero-touch enterprise PKI, and physical hardware hacks.

main Branch elastic-direct Branch

Instead of buying a loud, power-hungry server rack, I built a quiet, compact 3-node cluster using HP EliteDesk and ProDesk Mini G4 PCs mounted under my DIY desk shelf.

Rather than wrapping everything inside heavy virtual machine hypervisors like Proxmox, Mik Mak Muk runs directly on bare-metal CachyOS. Using Ansible, the project builds a fast, rock-solid baseline OS layer before deploying workload such as multi-node Elasticsearch 9 & Kibana cluster or running distributed llama.cpp AI cluster for embedding and inference as initial experiments.

In future experiments I will explore systemd containers, incus and K0s with Cillium

Design Choices

Building on compact 8th-Gen mini-PC chassis comes with real hardware limits.:

SATA Drive Caddy issues

All nodes run OS and data strictly on high-speed NVMe drives. However, removing the unused 2.5" SATA caddy to save space breaks cooling: on 65W models like mik, the CPU fan mounts directly to the SATA bracket! Removing it causes the CPU fan to ramp up to 100% full speed permanently. We keep the empty caddys installed solely to maintain stock fan mounting and quiet airflow. On 35 watt TDP models I might consider removing the caddy later to install networking via issue.The 65 Watt Elite Desk model does have two Nvme slots. The second one is unusable for normal NVME SSDs when the caddy is kept. A 30mm SSD does fit. I originally had old 120Gb SSD drives in two machines. given 2026 storage prices I decided to postpone adding big Sata SSDs or adding an extra Nvme SSD to my elitedesk machine. the 120 Gb SSDs were moved to another project.

2.5 GbE USB-C Option Port Networking

  • HP never made official 2.5 GbE option modules for 4th gen chassis
  • Thunderbolt is exclusive to EliteDesk (missing on ProDesk) and the required option port modules are rare
  • M.2 Wi-Fi/NVMe network adapters require custom 3D-printed rear covers to slot in the option port
  • 10 GbE USB adapters throttle under heat.
  • Adding USB-C 2.5 GbE dongles via Type-C option slots provides a clean, cheap 2.5x speed boost over the 1 GbE onboard port without MacGyver hacks.

Automated Network Benchmarking & Routing

As the old Dutch proverb goes: "Meten is weten" ("To measure is to know"). We built an automated full-mesh iperf3 benchmark playbook to verify line-rate throughput across both network tiers (1 GbE management and 2.5 GbE cluster interconnect). With jumbo frames we get 2.48 Gbps. Without jumbo frames we get 2.36 Gbps. On the 1 gb link we get 0.93 Gbps.

  • Jumbo Frames (MTU 9000): Configured exclusively on the isolated 2.5 GbE backend to eliminate L2-L4 protocol overhead and maximize TCP payload transfer speed (~2.36 Gbps payload saturation).
  • Zero Default Gateway on 2.5 GbE: The 2.5 GbE network runs strictly flat-L2 without a default route. Internet and management traffic route solely through the 1 GbE interface (MTU 1500), avoiding routing asymmetric bugs or PPPoE related MTU drops at the gateway.

Tales from the Lab: Lockouts & Vogon PKI

The Great pam_faillock Incident: Shortly after setting up the bare-metal OS, a few mistyped passwords during background Ansible tests triggered CachyOS brute-force protection (pam_faillock). The system assumed I was hacking myself and completely locked my personal login account out of sudo! The clean fix was creating a dedicated myansibleuser account with passwordless sudo and dedicated ED25519 SSH keys, keeping personal human accounts separate and password-protected.

Repository Branch Breakdown

main Base OS & Kernel Tuning

  • Mitigations Off: Disables Spectre/Meltdown kernel mitigations (mitigations=off) to recover up to 25% CPU performance in an isolated homelab.
  • NVMe Sleep Fix: Sets nvme_core.default_ps_max_latency_us=0 to stop deep power-saving states from dropping drives into read-only mode.
  • Intel Plundervolt Handling: Safely removes software undervolting to prevent systemd service crashes caused by HP BIOS microcode locks.
  • USB Network Routing: Configures 192.168.107.0/24 for inter-node transport with zero default gateway conflicts.

elastic-direct Native Systemd Stack

  • Native Arch PKGBUILDs: Compiles Elasticsearch and Kibana directly into .pkg.tar.zst packages using custom Jinja2 templates.
  • Native Systemd Services: Runs directly on host, without Docker/Kubernetes containers.
  • Automated CA & Token Handling: Generates Root CA certificates, exports browser trust files to ~/Desktop, and fetches kibana-ansible-token dynamically over HTTPS.
  • Dual-Subnet Binding: Restricts node transport sync (port 9300) strictly to the fast 2.5 GbE USB network.
  • UFW managed firewall settings I did not forget setup and teardown of firewall rules.

Declarative Lifecycle Execution

Management is clean, simple, and 100% idempotent:

  • ./controller-setup.yml — Creates dedicated local ED25519 SSH keys.
  • ./ansible-user-setup.yml -K — Bootstraps the automation account (requires password once).
  • ./setup.yml — Builds packages, issues certificates, tunes kernel parameters, and starts services.
  • ./reboot.yml — Executes rolling single-node restarts using --limit.
  • ./teardown.yml — Gracefully stops systemd services, removes pacman packages, and purges credentials.

What's Next? Jina Ebook Vectorization & Cluster Inference

  • Jina AI Ebook Vector Pipeline: Harnessing Jina AI embedding models across both Intel UHD 630 iGPUs (via Vulkan) and AVX2 CPU cores simultaneously. We vectorize entire Calibre EPUB ebooks into Elasticsearch 9.
